1.	How can I ensure that my Code, program, or software is functional and secure?
I can ensure that my software is functional and secure by developing and testing it against clearly defined requirements. In the CS 320 course, I learned that writing code is only one part of software development. The code must also be tested to determine whether it behaves as expected under both valid and invalid conditions. 
For the Project One assignment, I used JUnit tests to verify that the classes met their specified requirements. I created tests for valid inputs as well as invalid inputs. For example, the Contact class was tested to ensure that a contact could not be created with a null ID or an Invalid phone number. I also tested the service classes to verify that contacts and tasks could be added, updated, and deleted correctly.
I also learned the importance of code coverage. I learned that an application can pass a test but has not fully covered what the java classes need to tests. Running code coverage helped me identify which areas of my code were not covered in my unit tests and add additional tests to those methods. 
Security also requires validating input instead of assuming that users will always provide correct information. validation in classes such as Contact, Task, and Appointment prevents invalid data from being stored. In my future projects, I would also incorporate additional security practices such as authorization, authentication, secure data handling, and testing for vulnerabilities. 
2.	How do I interpret user needs and incorporate them into a program?
I interpret user needs by first identifying the specific requirements and then translating each requirement into functionality that can be implemented and tested. For example, in the CS 320 Project One assignment, I identified the specified requirements such as maximum field lengths, required fields, unique IDs, and which fields could be updated. 
For Instance, the Contact requirements stated that the contact ID could not be null, could not exceed 10 characters, and could not be updated. Instead of simply assuming these requirements were satisfied, I implemented validation in the Contact class and created JUnit tests to verify each condition. I used the instructor feedback to guide me on the areas that had not been covered, treating him as a user. I looked through the feedback, identifying requirements that I had not tested and used the feedback to build tests for the preceding milestones. 
3.	How do I approach designing software?
I approach software design by first understanding its requirements and then breaking the system into smaller components with clearly defined responsibilities. I consider what data each class needs to store, what operations need to be performed, and how those operations should interact. In my CS 320 project one, I demonstrated this by separating the data classes and service classes. I also approach design with maintainability in mind.
